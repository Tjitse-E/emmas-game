# Moon Meadow Home 1.0.1: plan from Emma's first play

Status: planned on 2026-10-12, not built yet.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Answer Emma's feedback on Wave A (2026-10-12) with four features and nothing else: harder eggs, hungry wishes and a food tray in the meadow, the lantern walk into the stable at goodnight, and feeding at the mangers in the stable. The release is `1.0.1`. Wave B content stays unloaded.

**Architecture:** The same app (`games/moon-meadow-home/`, called `G` below) and the same rules as `docs/v3/plan.md`. Pure rules go in `src/core/`, scenes in `src/scenes/`. No new event type is added: every new act is written with an event that core's validator already accepts (section 3.3). One new moment kind (`hay-rack`) and one new release value (`1.0.1`) are added once, by the integrator, before the lanes start. Five lanes (eggs, feed, night, integ, art) own disjoint files and build in parallel worktrees. Audio is generated by the integrator before the worktrees are made, so every lane has the clips.

**Tech stack:** unchanged (Node 24.19.0, Svelte 5.57.2, Vite 8.3.4, TypeScript 6.0.3, Vitest 5.0.3, `playwright-cli` 0.1.8 with WebKit, ElevenLabs through `scripts/generate-audio.py`, Codex image generation through the subscription).

**Read first:** `docs/v3/decisions.md` (the heading "2026-10-12, after Emma's first play of Wave A" holds the binding decisions for this plan), `docs/v3/plan.md` Global Constraints and section 2.1 (R1 to R64 still bind), `docs/v3/plan/contracts.ts`.

## Global constraints

- Everything in `docs/v3/plan.md` Global Constraints still holds: British English only, no Dutch anywhere, unicorns only, no timers, streaks, countdowns, buzzers or red crosses, everything Emma must understand is spoken from a pre-generated clip and shown with pictures, never browser speech.
- Port 8765 and `dist-emma` are Emma's. No lane touches them. Lane ports are 8781 to 8785 (section 4).
- Each lane commits only the paths it owns (`git add <paths>`, never `git add -A`, never `git stash`, never a reset or checkout of a file it does not own). Plain English commit messages, no AI attribution, no em dashes. A commit that fails on `index.lock` is retried after 2 seconds.
- Tests first where practical. `npm test` and `npm run check` stay green for the lane's own files.
- Agents never read, print, source or copy the dotenv file. Scripts load it themselves. Sandbox exceptions (`dangerouslyDisableSandbox: true`): npm install, playwright-cli, codex, ElevenLabs generation, servers on ports.
- Browser checks: `playwright-cli` only, WebKit iPad emulation at 1180 x 820, 1080 x 810 and 1024 x 768, short session names without slashes, screenshots in `$TMPDIR/mmh-shots/`, `mousemove`/`mousedown`/`mouseup` on pulsing elements, sessions closed and servers killed afterwards.
- Older Safari: no CSS `offset-path` and no `Array.prototype.findLast` in runtime code (Safari 15.0). Movement along a path is a list of points animated with `transform`.
- Every subagent runs on `opus`.
- Out of scope (Tjitse, binding): feeding bowls with sharing or halves, labelled food bins, bedtime wishes, all of Waves B and C. Do not build them.

```ts
// The seam between the goodnight stable (lane night) and the mangers (lane feed). docs/v3/next/plan.md section 3.7.
/** One manger on screen: the stall's baby, its door number, and the manger centre in stage pixels (1180 x 820). */
export type MangerSpot = { baby: string; order: number; x: number; y: number };
/** The checked moment's test hook, forwarded by the goodnight scene hook while it is open. */
export type StageHook = {
  answer(): Promise<unknown>;
  wrong(kind?: string): Promise<unknown>;
  idle(): void;
  /** aria-label of the thing to drag (an item, a bundle), or null. */
  target(): string | null;
  /** aria-label of where it goes ('manger 7', 'hay rack'), or null. */
  drop(): string | null;
};
export type MangerFeedProps = {
  /** Mangers on screen, walked babies first, top row before bottom row. Empty: nothing to feed. */
  spots: MangerSpot[];
  /** The checked moment's hook while it runs, null when there is none (free feeding). */
  onhook: (h: StageHook | null) => void;
  /** Called once when the checked moment is over or there was none. The tray stays for free feeding. */
  onchecked: () => void;
};
```

## 15. Merge, batch check, gate and release

1. **Batch 1** (parallel): eggs, feed, night, integ, art, each in its worktree, each running its own tests and in-lane flows on its own port.
2. **Merge** (integrator, main tree): `git merge --no-ff lane/<lane>` for art, eggs, feed, night, integ in that order. Files are disjoint, so a conflict means a lane broke ownership: stop and give the file to its owner. Remove the worktrees.
3. **Batch check:** `npm test`, `npm run check`, `npm run check:content -- --assets=warn`, `npm run check:audio`, `npm run simulate`.
4. **Batch 2** (cross-lane flows, integrator with the owners on call): `heartbeat/stable-feeding`, `heartbeat/heartbeat`, `integration/upgrade`, then the rest of `gate-1.0.1.txt`. A failing flow goes to the owner of the failing file for a short fix lane.
5. **Gate:** `bash tools/gate.sh 1.0.1` (port 8766, `dist-test-gate`).
6. **Release:** after the gate passes, `bash tools/promote.sh`. Emma's server keeps serving `dist-emma` and picks up the new build on her next page load. Then update the status line at the top of this file and IDEAS.md.
